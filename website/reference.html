Every agent has these. repo is owner/name and can be omitted: it is inferred from the origin remote of the agent's working directory.

Changing an individual permission makes the policy Custom unless it matches a preset.

Rules

A rule has an effect (allow or deny), repository patterns, actions (or all), and an optional reason that is shown to the agent in the denial. For each needed action: a matching deny rule denies; otherwise a matching allow rule allows; otherwise the default permissions decide. Rule order does not matter.

Patterns are owner/repo, case-insensitive. * matches any run of characters inside one part: acme/*, */docs, acme/web-*. A lone * matches every repository.

Allowed owners

Checked before the policy. Exact, case-insensitive; * allows all; the default is *; an empty list refuses everything. Paths that name no owner (/user/repos, a search without repo:, org: or user:, a GraphQL call without repo) are refused unless * is allowed.

The page

  • Overview: remaining and limit per credential (gh and each GitHub App) and resource, a reset countdown, a requests-per-minute chart, the cache hit rate, and banners when a limit is nearly or fully used up or no owner is allowed.
  • Auth: source choice, gh check, the list of GitHub Apps (add, edit, remove, owners, default, test connection), fallback toggle, allowed owners.
  • Policy: presets, default permissions, rules, the dry-run box, the soft rule, the cache TTL.
  • Activity: a live log of calls per agent: tool, repository, allowed, cached, revalidated, denied or failed, HTTP status, the source (and the App that served it) and duration. Tap a row for the full message.
