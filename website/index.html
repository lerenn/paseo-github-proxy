One front door to GitHub for every agent

GitHub Proxy adds a small set of github_* tools to every Paseo agent and puts your rules, a shared cache and rate-limit handling between the agents and GitHub. Read-only by default.

Agents list and read pull requests, issues, commits, files, checks, releases, workflow runs and logs, labels, projects and repositories, and search. When you allow it they also comment, review, open issues and pull requests, edit and label them, create branches, write files, manage releases and workflow runs, merge and delete branches. A generic github_api tool (REST and GraphQL) covers the rest, and only works where the policy allows it.

Policy you controlRead-only, PR workflow or full, plus allow and deny rules per repository pattern. A denial names the rule, so the agent stops retrying.
Fewer API callsA shared in-memory and on-disk cache with ETag revalidation: many agents asking the same thing cost one request.
Rate limits handledLive remaining and limit per credential, a "retry at HH:MM" error when exhausted, and an optional fallback to the other credential.
