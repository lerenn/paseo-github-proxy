# Parity with the gh CLI

**Status**: Accepted. Extends the tool set of `2026-11-24-in-plugin-proxy.md`; the policy model is unchanged.

## Context

The proxy offered about seventeen tools: pull requests, issues, checks, branches, search, repository info and the generic `github_api`. Agents that are told to use the `github_*` tools instead of `gh` kept hitting gaps (diffs, labels, releases, workflow logs, file contents, projects) and fell back to `github_api` (which is classified as a generic write and often denied) or to `gh` itself. `docs/gh-parity.md` compares every `gh` command group with what the proxy offers.

## Decision

1. **Curated tools for every network `gh` command that is useful to a coding agent.** Each has a typed input, a description and a declared policy action; none is classified from a path (`proxy.rest` and `proxy.graphql` receive `actions`).
2. **Operation tools.** Related operations sit behind one tool with an `operation` enum (`github_actions`, `github_releases`, `github_labels`, `github_contents`, `github_commits`, `github_pr_manage`, `github_repo_manage`, `github_repo_config`, `github_account`, `github_gists`, `github_project`), plus `github_update_issue` and `github_edit_comment`. About thirty tools in total rather than a hundred: a long tool list costs every agent context on every turn. Required fields of one operation are validated at run time with a message that names the operation, since a union schema is heavier for the model. Each operation declares its own action, so `github_actions` needs `read` to list runs and `manage_actions` to re-run one.
3. **New actions**, in `shared/actions.ts`, the presets, `classify.ts`, the README and `docs/policy.md`: `create_branch`, `write_file`, `manage_labels`, `manage_release`, `manage_actions`, `manage_variables`, `create_repo`, `edit_repo`, `manage_gists`, `manage_notifications`, `manage_project`. Reads stay `read`. The PR workflow preset adds only the low risk `create_branch`, `manage_labels` and `manage_notifications`; the read-only default is unchanged. Edits of issues and PRs (labels, assignees, lock, reviewers, ready, update branch, comment edits) reuse `update_pr`; auto-merge and syncing a fork reuse `merge`. `github_api` is classified to the same actions, so it still cannot bypass a rule on a specific action.
4. **Proxy changes.** `rest` takes an `accept` header (raw diffs); it is part of the cache key, so a diff and the JSON of one URL are cached apart. `graphql` takes `actions` and an `owner` from curated tools whose document is fixed in code (marking a PR ready, auto-merge, review threads, projects): they are checked as stated and are not parsed for scoping. A write invalidates the cached reads of its repository, or of its account or collection (`/orgs/acme`, `/gists`, `/notifications`), or every cached GraphQL read.
5. **Safety.** Secret values are never read or set: `github_repo_config` returns secret names only, and there is no `secret set` (it needs the value sealed with the repository key, and an agent should not handle it). Resolving a review thread, whose id is global, first checks that the thread belongs to the pull request that was named. Creating or forking into another owner checks that owner against the policy. Account level paths (`/user/orgs`, gists, notifications) name no owner and are denied unless `*` is an allowed owner. Visibility changes, renames, archiving, deleting repositories, ruleset and protection writes, ssh and gpg keys and deploy keys are left to `github_api`, so they need `generic_api_write`.
6. **Out of scope**: what needs a local checkout, a terminal, an interactive prompt, a browser, binary transfers or the local CLI, with the reason in `docs/gh-parity.md`.
7. The tools live in `server/tools.ts` (the earlier ones), `server/tools-pr.ts`, `tools-repo.ts` and `tools-account.ts`, on shared helpers in `server/toolkit.ts`, to keep each file readable.

## Consequences

- An agent with the PR workflow preset can label, assign, ready and review pull requests, create branches and read workflow logs, but cannot write files, release, run workflows or merge until the user allows those actions.
- Stored policies keep their action list: the new actions are denied until the user checks them in the Policy tab, which lists them from the catalog.
- More tools means a larger tool list for each agent; the operation grouping bounds it.
- Job logs are the end of one job's text log (the run level zip is binary); artifacts are listed, not downloaded.
- GraphQL curated documents depend on GitHub's schema (`markPullRequestReadyForReview`, `enablePullRequestAutoMerge`, `resolveReviewThread`, Projects v2).
